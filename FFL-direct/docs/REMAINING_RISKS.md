# Оставшиеся риски FFL Driver Direct 0.2.2

Дата: 17.10.2026. Область: собственная восстановленная тестовая копия. Это не разрешение обращаться к production.

## Препятствие распространению водителям

**Критический риск: общий DB account в APK. DRIVER_ROLLOUT_READY недопустим.**

Повторная независимая проверка тем же account подтвердила:

- доступность столбца parol водителей и чужих исходных заказов;
- возможность UPDATE двух delivery columns чужого fictional заказа без штатного клиента;
- отсутствие серверного связывания DB account с конкретным driverId/access.

Probe изменял только выделенную fictional строку и был откатан. Отказы UPDATE status/auth, INSERT и DELETE подтверждены. SELECT приложения сокращён со всей БД до7контрактных таблиц; независимый integrity auditor хранится отдельно и не встроен в Main APK. Внутри разрешённых таблиц чтение parol/чужих строк по-прежнему возможно. TLS, VPN, R8, скрытый BuildConfig, повторный access SELECT и column grants не исправляют этот риск. Точный password match в 0.2.2 устраняет collation-ошибку штатного login, но не защищает от извлечённого DB account и модифицированного клиента.

Настроенный локальный APK хранится приватно: его DB-пароль извлекается из DEX. Публичные APK/исходники не содержат этой конфигурации. Не распространять настроенный тестовый APK как производственный, не открывать loopback MariaDB наружу, не подключать root/production credentials.

## Практический вариант без отдельного VPS

Если существующий хостинг компании поддерживает PHP, HTTPS и локальный доступ к этой MariaDB, небольшой серверный шлюз можно разместить там же. Наличие такой возможности и разрешения хостинга ещё не проверены; бесплатность и инфраструктурный доступ не обещаются.

Минимальный объём: login и отзыв сессии, active drivers без parol, orders/details/directory/summary, delivery transaction. DB password остаётся на сервере. Сервер выводит driverId из проверенной сессии, принудительно фильтрует каждое чтение/запись, повторяет access checks и transaction postconditions, ограничивает перебор паролей. Пароли постепенно переводятся в проверяемые password hashes; migration не выполняется этим аудитом. Gateway не обязан быть FastAPI и не требует JWT: допустимы непрозрачные отзываемые session tokens.

Это отдельное изменение транспорта/repositories, а не скрытый fallback текущего Direct APK. В этом проекте API не добавлен. Серверную часть/права/production DDL следует проектировать и проверять отдельно. Альтернатива — индивидуальные DB identities с серверными views/procedures и закрытыми базовыми таблицами; общий account с параметром driverId в процедуре без серверной аутентификации недостаточен.

## Ограничения подтверждённой готовности

| Риск / проверка | Фактическая граница |
| --- | --- |
| Физический телефон, сеть компании/VPN/сертификат реального сервера | Не проверены. Emulator+adb reverse+локальная CA не доказывают работу этих условий |
| Android24/36, OEM, Android13+ notification permission | Runtime проверяется на API30. Более новые/старые API и реальные permission dialogs не заменяются source inspection |
| Периодические 15мин, Doze, reboot, battery restrictions | WorkManager ограничен Android. OneTimeWorker SQL/notification/tap не доказывает эти режимы и точность интервала |
| Force-stop | Android может не запускать фоновые jobs до явного открытия приложения; непрерывное получение не обещается |
| Потеря уведомления | seen сохраняется до notify: crash между ними может потерять уведомление; эта политика предотвращает повтор, не даёт exactly-once delivery |
| Summary consistency | Counts и IDs читаются двумя SELECT, не единым snapshot; UI refresh остаётся источником текущего состояния |
| Сдача и разрыв при commit | Может остаться UNKNOWN. Автоматического повтора нет; требуется безопасное повторное чтение текущего заказа |
| Отзыв доступа | Shared lock сериализует штатную transaction с изменением auth row. Уже начавшаяся сдача может завершиться до commit отзыва; это не серверная защита от другого SQL-клиента |
| Локальная сессия | ID/name/version — hint, не криптографическая identity. Изменение DataStore на rooted/debug устройстве не предотвращено |
| Отказ очистки storage | Выход сразу блокирует восстановление в текущем процессе. Если disk clear не состоялся, сохранённый hint может пережить процесс; интерфейс сообщает storage error. Серверное отзывное удостоверение здесь отсутствует |
| JDBC cancellation/DNS | IO, timeout policy и socket bounds есть; жёсткую остановку произвольного native call ровно через15с не обещаем |
| Производительность | Замеры loopback/TCG не равны мобильной сети/физическому телефону. Нет нагрузочного multi-device/soak/heap-leak сертифицирования |
| Индексы | date/id_v lookup и TRIM contact lookup требуют отдельного DBA анализа; production индексы не изменялись |
| Legacy triggers | UPDATE может создавать audit/BF записи. Сохранены исходные trigger bodies; DBA должен подтвердить production side effects |
| Время | NOW использует timezone сервера; дата по умолчанию — локальный день телефона. Business timezone/границы суток production не подтверждены |
| Старый UI | Есть source comparison и screenshots нового UI, без одинакового runtime dataset старого API приложения; pixel-perfect parity не заявлена |
| Яндекс/звонки | URI/Intent/copy проверяются; реальные Карты/Навигатор/телефонный вызов отдельно не выполнены |
| Windows | Инструкции и кроссплатформенные пути подготовлены; запуска на Windows не было |
| Подпись и распространение | Debug key — только developer build. Production applicationId, ключ, delivery channel и revocation policy не назначены |
| Публикация среды | Сохранённый draft не равен publish и не гарантирует сохранение живых процессов. Дамп/ключи/настроенные APK должны оставаться в приватной среде |

Фактический результат minified runtime следует брать из FINAL_TEST_RESULTS: unsigned R8 build сам по себе не означает успешный запуск. Системные ANR software эмулятора сохранены отдельно и не объявляются отсутствием ANR на телефонах.

## Что нужно до пилота и распространения

Для внутреннего тестирования использовать только приватную локальную копию, fictional write scope и независимый package. Перед пилотом на одном телефоне: безопасная конфигурация тестового сервера, полная установка/сценарий на конкретном устройстве, реальная сеть/CA, звонки/маршруты, permission/Doze/reboot и согласованная обработка UNKNOWN. Доступ к настоящим данным требует принятого серверного разграничения; shared account не считается приемлемым ограничением массового rollout.

Перед распространением: серверно-принудительная driver isolation и отзыв, закрытый parol, независимые отрицательные тесты SQL/HTTP-клиентом, нагрузочные/операционные проверки, production signing/distribution и понятный rollback без изменения уже сданных заказов. Эти действия не выполняются автоматически этим аудитом.
