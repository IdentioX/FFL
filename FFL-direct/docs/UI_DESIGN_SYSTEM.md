## Типографика и размеры

Используется системный Android Sans Serif с поддержкой кириллицы, без сетевых шрифтов. Размеры — sp; системный font scale сохраняется.

| Стиль | Размер / интерлиньяж | Начертание |
| --- | --- | --- |
| Приветствие | 23 / 29sp | Bold |
| Заголовок раздела | 16 / 22sp | SemiBold |
| Номер заказа, название контакта | 14 / 20sp | SemiBold |
| Основное значение | 15 / 21sp | Regular |
| Вторичный текст | 13 / 19sp | Regular |
| Подпись строки | 11 / 16sp | Regular |
| Нижняя панель | 10 / 14sp | Medium, до двух строк |

Основные поля экрана — 16dp, для списка заказов — 12dp. Интервал секций — 10dp. Карточки имеют радиус18dp, поля13dp, кнопки14dp, чипы7–8dp, верх панели22dp. Слабые тени используются для поверхностей и центральной кнопки, без тяжёлых обводок. Высота строки заказа минимум60dp; при большом шрифте строка увеличивается. Основная кнопка минимум50dp. Круглая телефонная кнопка имеет визуальный диаметр40dp с увеличенной интерактивной областью; в компактных контактах деталей используется40dp.

Токены отступов и компоненты находятся в `ui/FflDesignSystem.kt`: FflCard, FflPrimaryButton, FflSecondaryButton, FflRoundAction, FflAvatar, FflSearch, FflStatus, FflStatePanel. Иконки рисуются локальным единым 24-unit outline набором FflIcon; фото водителей и внешние ресурсы не загружаются.

## Главный экран

Все три секции одновременно находятся в одном LazyColumn:

1. Первый рейс.
2. Второй рейс.
3. Сданные заказы.

Секция — единая белая поверхность со скруглёнными внешними углами, заголовком и счётчиком. Строки используют стабильный ключ полного `OrderId.wire`, например `reys:1` и `reys_den:1`. Один numeric ID разных таблиц не объединяется.

Строка содержит индикатор, исходный номер, число накладных, текст готовности, звонок и chevron. Клиент, адрес и подробный комментарий доступны в деталях: они не растягивают каждую строку. Маркер номера не дублируется, если он уже есть в исходном значении. Сданные строки приглушены, просмотр и звонок доступны.

Готовность берётся из существующих полей status/quantityReadiness/isDelivered. Частичная готовность не становится полной; право на сдачу по-прежнему определяется действующим доменным правилом status==2. Пустая секция показывает «Заказов нет». Заголовок секции позволяет прокрутить список к ней.

## Панель из пяти действий

Порядок неизменен: **Домой | Справочник | Обновить | Сортировка | Настройки**.

Пять равных зон обеспечивают точный горизонтальный центр обновления. Центральный круг56dp выступает над белой панелью; под выступ зарезервировано место, верх круга не обрезается. Остальные иконки24dp. Учитываются status/navigation bars и IME; содержимое получает фактическую высоту панели через Scaffold. При открытой клавиатуре панель скрывается, поля и кнопки авторизации доступны через IME padding/scroll. На авторизации панели нет. Диалоги используют собственные модальные окна, без панели внутри окна диалога.

Активный раздел и включённая сортировка выделяются primary. На главном/втором рейсе сортировка доступна; в справочнике, деталях и настройках она отключена. Обновление контекстное: заказы, справочник или текущие детали. В настройках, где нет соответствующего запроса, оно отключено. Во время запроса центральная иконка вращается, повторное нажатие блокируется; ViewModel дополнительно предотвращает дублирование.

Pressed state задают Compose clickable/buttons, тактильная обратная связь применяется при действиях панели и начале перетаскивания. Названия и состояния доступны через semantics. На дочерних экранах Back возвращает назад; из справочника также доступно аппаратное Back/Домой.

## Ручная сортировка

В режиме сортировки вместо правых действий показывается ручка. Удержание запускает перенос: строка получает тень, небольшой подъём и смещение; соседние строки используют animateItem. Перемещение на соседнюю позицию вызывает существующий WorkspaceViewModel.move с исходным OrderSection/OrderId. На краях есть прокрутка; пересечение границы секции не переносит заказ в другую секцию. Для accessibility предусмотрены действия «Поднять заказ»/«Опустить заказ».

Порядок хранится прежним WorkspacePreferences.order по driver/date/section. Новые SQL IDs добавляются после сохранённых, удалённые исчезают. sort_r в MySQL не меняется. Сброс порядка доступен в подсказке режима сортировки, завершение — повторным нажатием четвёртого действия.

Объединённая страница сохраняет прокрутку по driver/date под новым локальным ключом section=-1. Старые координаты вкладок0..2 не удаляются; после перехода на новую композицию начинается отдельная история прокрутки. Обновление текущего списка не пересоздаёт LazyListState и не сбрасывает дату/порядок/позицию.

## Авторизация, детали, справочник и настройки

Выбор водителя: бренд, приветствие, поиск, аватары, активность, выбранная строка и продолжение. Список inactive из макета не копируется: реальный getDrivers возвращает только разрешённых активных водителей.

Пароль — отдельная страница с выбранным водителем, показом/скрытием, IME Done, loading/error. Значение не rememberSaveable, очищается при фоне/выходе/отправке, не попадает в настройки или сессию. Пустой пароль не отправляется. Backend IP отсутствует. Отдельный административный редактор Direct MySQL добавлен в0.3.1 по новому запросу пользователя.

Детали используют те же DAO/resolver/models. Карточки клиента, адреса, времени/накладных, контактов, комментария и истории не меняют данные. Неоднозначный адрес явно помечен; маршрут проверяет актуальные ownership/access и использует прежний allowlist URI. Номера из примечания доступны через телефонную кнопку; исходное примечание — через Info. История компактно показывает первых двух из последних пяти, раскрытие показывает остальных, строка водителя раскрывает исходный заказ и его телефон/WhatsApp. Звонок и копирование сохранены.

Справочник: поиск по имени/телефону, категории «Важные», «Водители», «Все», карта/владелец и исходные номера. Категория менеджеров не выдумывается: такого отдельного набора в контракте справочника нет. Контакты менеджера остаются в деталях заказа.

Настройки: реальная рабочая дата, opt-in уведомлений второго рейса, тема, версия и выход. Периодическая фоновая проверка описана честно: примерно15мин с ограничениями Android, не автоматическое обновление открытого списка. Неработающий переключатель звука не добавлен.

Сдача — модальный диалог с номером, «Да, сдал»/«Отмена», одноразовым подтверждением. Для long-press строки сохранён пятисекундный guard; в деталях обычное явное подтверждение. UI вызывает прежнюю транзакцию, проверку access/id_v и idempotency.

## Визуальная приёмка

Основной baseline — Android360dp ширины, дополнительные проверки320dp и fontScale1.6. Используются реальные снимки установленного APK с синтетическими данными, не изображения Preview. Фото/имена/даты/адреса из макета не становятся данными приложения. Скриншоты не подменяют отдельную проверку настоящего MySQL-пути.

Результаты, команды, точные APK SHA и оставшиеся отличия — [UI_IMPLEMENTATION_REPORT](UI_IMPLEMENTATION_REPORT.md). Системные Android status bar/клавиатура/навигация сохраняются; iOS notch и цифровая клавиатура из иллюстрации не рисуются поверх Android.

## Подключение Direct MySQL (0.3.1)

Отдельный административный экран продолжает палитру и карточки приложения: заголовок с outline-иконкой БД, белая карточка параметров, поля со скруглением 14 dp, маскированный пароль с eye-action, обязательный TLS, CA PEM, карточка результата, основная фиолетовая кнопка проверки, вторичная кнопка сохранения и отмена. Экран прокручивается и учитывает системные insets/IME; нижняя рабочая панель внутри редактора не показывается. Сохранение недоступно до успешной проверки. Loading блокирует поля и повторный запрос. Дополнительный CA PEM необходим действующему `verify-full` контракту и отсутствует в упрощённой иллюстрации пользователя.

В главных настройках добавлена строка «Подключение к БД». На входе администратора доступна только ссылка на отдельный редактор, а не поля реквизитов. Конфигурация не является backend IP flow.
